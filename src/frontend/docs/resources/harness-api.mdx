# Harness API

The harness API is the core MinuNotes surface for agents, scripts, OpenAPI tools, and MCP adapters. API keys can access all non-private folders, selected project roots, or explicit specific folders.

## Auth

Send the API key with every request:

```http
X-API-Key: ntak_...
Content-Type: application/json
```

## Folder access

API keys can use one of two folder access modes:

- **All non-private folders**: access every non-private folder, including future non-private folders.
- **Project roots**: access selected top-level folders and their non-private subfolders.
- **Specific folders**: access only folders explicitly listed on the key.

Folder-level read-only blocks Create/Edit for All and Project-root scopes. Specific folder grants can be used as explicit write exceptions. Private folders are excluded from API, MCP, and integration access. A private parent also makes its child folders private for API access.

Folder creation is separate. Only keys with folder-creation permission can call:

```txt
POST /v1/harness/folders
```

Agents can move notes when the key can edit every source folder and create in the target folder. Cross-root moves work only when both sides are inside the key's granted scope.

```bash
curl -s -H "X-API-Key: ntak_..." -H "Content-Type: application/json" \
  -X POST "$API/v1/harness/notes/move" \
  -d '{"noteIds":["note_xxx","note_yyy"],"targetFolderId":"folder_xxx"}'
```

Move responses return compact note metadata and no content.

## Trash boundary

The harness API exposes active content only. Trashed notes, templates, and folder subtrees are omitted from folder lists, search, line search, tags, graph results, and attachment access. Direct requests for trashed IDs return not found.

Harness and API-key clients cannot list Trash or trash, restore, or permanently delete content. Owners must use the authenticated MinuNotes web interface. A not-found response can also mean the item is outside the key's scope, so it does not prove permanent deletion.

## Safe editing flow

1. Search or list folders.
2. Read the note.
3. Capture `contentHash`.
4. Send small edits with `baseHash`.
5. Read back the note and report final markdown or a changed-section summary.

Create and update responses return compact note metadata plus `contentHash`; they do not include full note `content`. Use the read-note endpoint when content is needed.

## Canvas notes

Canvas notes use `documentType: "canvas.default"` or `"canvas.mindmap"`. Their `content` is serialized JSON Canvas, not markdown. Markdown patch edits are rejected for canvas notes.

Create from JSON Canvas:

```bash
curl -s -H "X-API-Key: ntak_..." -H "Content-Type: application/json" \
  -X POST "$API/v1/harness/canvases" \
  -d '{"folderId":"folder_xxx","title":"Flow","canvas":{"nodes":[],"edges":[]}}'
```

Create from Minu diagram syntax:

```bash
curl -s -H "X-API-Key: ntak_..." -H "Content-Type: application/json" \
  -X POST "$API/v1/harness/canvases/from-syntax" \
  -d '{"folderId":"folder_xxx","syntax":"diagram \"Product plan\" {\n  layout mindmap\n  Product\n  Product > Research\n}"}'
```

Replace an existing canvas:

```bash
curl -s -H "X-API-Key: ntak_..." -H "Content-Type: application/json" \
  -X PUT "$API/v1/harness/notes/note_xxx/canvas/from-syntax" \
  -d '{"baseHash":"hash_from_read","syntax":"diagram \"Auth flow\" {\n  User > Login\n  Login > Dashboard\n}"}'
```

Use syntax for generated diagrams/mind maps. Use raw JSON Canvas for exact imports or deterministic replacements.

### Link canvas nodes to notes

Canvas and mind-map nodes can reference MinuNotes notes through host metadata:

```json
{
  "id": "node_a",
  "type": "text",
  "text": "Project plan",
  "minunotes": {
    "link": { "type": "note", "id": "note_target" }
  }
}
```

Use focused endpoints to add or remove an internal note link without replacing the full canvas:

```bash
curl -s -H "X-API-Key: ntak_..." -H "Content-Type: application/json" \
  -X POST "$API/v1/harness/notes/note_canvas/canvas/nodes/node_a/link-note" \
  -d '{"targetNoteId":"note_target","baseHash":"hash_from_read"}'

curl -s -H "X-API-Key: ntak_..." \
  -X DELETE "$API/v1/harness/notes/note_canvas/canvas/nodes/node_a/link?baseHash=hash_from_read"
```

Linking requires edit access to the canvas and read access to the target note. Internal links contribute to backlinks and graph results with `linkType: "canvas-note"`.

External web links remain in the standard JSON Canvas `node.url` field. Internal link/unlink operations preserve `node.url` and unrelated node metadata, so a node can contain both an external URL and an internal note link.

## Edit payloads

```ts
type DocumentEdit =
  | { type: "append"; text: string }
  | { type: "replace_text"; oldText: string; newText: string }
  | { type: "replace_range"; from: number; to: number; text: string };
```

Prefer `replace_text` when the target text is unique. Use `replace_range` only after reading lines or sections.
